# internal/ · 密卷

本目录存放**不入正文**的教内密卷。里面的东西经文体例上属"密"字一脉，故单独存放，并做加密处理。

## 本目录的规矩

| 文件 | 是否入库 | 说明 |
|---|---|---|
| `<名>.md` | **不入库** | 明文。只存在您本机，由 `.gitignore` 挡住 |
| `<名>.md.enc` | 入库 | 密文。AES-256-CBC + PBKDF2，没有口令就是乱码 |
| `README.md` | 入库 | 本说明文件，不含任何密卷内容 |

**明文永远不进仓库，只进密文。** 这条是铁律：git 的历史是删不掉的，一旦明文进过一次，
即使后来删掉文件，它仍然留在历史里，任何人 clone 下来都能翻出来。

## 怎么用

需要 Git 自带的 `openssl`（Windows 上装了 Git for Windows 就有，Git Bash 里敲 `openssl version` 可验证），不需要另装任何工具。

**加密**（明文 → 密文，然后提交密文）：

```bash
python scripts/nrcrypt.py lock internal/正魔辨.md
git add internal/正魔辨.md.enc
git commit -m "密卷：正魔辨"
git push
```

**解密**（把仓库里的密文还原到本机）：

```bash
python scripts/nrcrypt.py unlock internal/正魔辨.md.enc
```

**看现状**：

```bash
python scripts/nrcrypt.py status
```

**校验**（CI 每次都会跑，防止明文误入库）：

```bash
python scripts/nrcrypt.py check
```

口令优先从环境变量 `NRCRYPT_PASSPHRASE` 读；没有则交互式输入，不回显。
口令经 `-pass env:` 传给 openssl，不会出现在命令行参数里，`ps` 看不到。

## 这套做法能挡什么、挡不住什么

**能挡住内容。** 仓库是公开的，但没有口令的人拿到的只是密文。
加密用 AES-256-CBC，密钥由 PBKDF2-HMAC-SHA256 迭代 60 万轮从口令导出，加随机盐。

**挡不住"存在"。** 密文的**文件名是公开的**——`internal/正魔辨.md.enc` 这个路径谁都能看见，
也知道它哪天改过、有多大。所以外人会知道"教内有这么一卷密卷"，只是读不到里面的字。
若连"有没有"都要保密，这个目录就不该出现在公开仓库里，得改用私有仓库。

**口令丢了，密文就废了。** 没有找回的余地。请把口令抄进密码管理器，
并自己留一份明文备份在仓库之外。

**密文不防篡改。** 谁都能把仓库里的 `.enc` 换掉。改了之后要么解密失败，要么解出错字。
以您本机的明文为准；若解出来的内容读不通，先怀疑密文被动过。

**改了就忘，会出岔子。** 明文改了但没重新 `lock`，仓库里还是旧版本。
`status` 会列出"明文比密文新"的文件，提交前扫一眼。
