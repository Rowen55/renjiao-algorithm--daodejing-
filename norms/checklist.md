# 发布前自查清单

按产品生命周期分五段。每条都能回答"是/否/不适用"，答不出来的就是需要补证据的地方。

用法：

1. 每次上线、重大模型更新、策略变更或监管新规出台后，从头跑一遍
2. 答"否"的条目记为**偏离**，写清补救措施与期限；答"不适用"的必须写理由，不得空置
3. 争议条目按 [`precepts.yaml`](precepts.yaml) 的 `conflict_resolution` 次序裁决
4. 全部结论填入文末的判定记录表并留档

---

## 一、设计立项

- [ ] **P01 不害** 是否存在可预见的误用会导致人身安全风险？若有，拦截、告知与人工复核通道是否已设计？
- [ ] **P01 不害** 是否存在会剥夺就业、入学、信贷、医疗等机会的自动决策？申诉与救济路径是否可用？
- [ ] **P04 不偏** 目标用户中是否有弱势或特殊群体（老人、残障、低收入、低识字率）？是否提供了替代方案？
- [ ] **P04 不偏** 界面是否支持字体调整、读屏、语音操作？旧机型与低带宽下是否可用？
- [ ] **P06 不蔽** 用户能否一键关闭个性化推荐或自动化决策？关闭后核心功能是否仍可用？
- [ ] **P06 不蔽** 涉及的算法推荐服务，基本原理、目的意图、主要运行机制是否有对外公示的位置？
- [ ] **P07 不扰** 推送权限默认是开还是关？免打扰时段是否生效？
- [ ] **P08 不囚** 是否保留了返回检索框或纯时间序列表的入口？
- [ ] **P10 不争** 核心考核指标是完成度还是停留时长？是否有健康度指标对冲？
- [ ] **法定** 是否属于具有舆论属性或社会动员能力的服务？是否需要安全评估与算法备案？（本经未覆盖，必查）

## 二、数据与训练

- [ ] **P02 不窃** 每个采集字段能否对应到具体功能？用途与保留期限是否已登记？
- [ ] **P02 不窃** 是否留存了可识别使用者身份的输入信息与使用记录？保留多久？如何删除？
- [ ] **P02 不窃** 是否有"不同意即不可用"的伪选择？核心功能是否真的依赖该数据？
- [ ] **P05 不执** 目标函数中是否残留已知会产生不公的代理变量（邮编、设备型号、消费习惯等）？
- [ ] **P09 不贪** 训练数据是否具有合法来源？知识产权与个人信息授权是否核查？
- [ ] **P09 不贪** 是否存在重复执行已知无效的训练任务？算力是否错峰调度？
- [ ] **P04 不偏** 训练数据的群体构成是否已统计并披露代表性缺口？
- [ ] **P11 不名** 用户上传的内容是否被纳入训练？是否告知并提供退出方式？
- [ ] **卷八 内观** 是否记录了数据的偏差来源与标注规则？
- [ ] **法定** 数据标注规则、质量评估与人员培训是否留痕？（本经未覆盖，必查）

## 三、上线前评估

- [ ] **P04 不偏** 是否完成分组公平性测试？各群体拒绝率、误差率差异是否在阈值内？
- [ ] **P05 不执** 上线门槛是否同时包含精度、公平、稳健三项？是否拒绝了"以精度换公平"的方案？
- [ ] **卷八 觉知** 模型能否识别并表达自身不确定？超能力边界时是否会拒答而非硬答？
- [ ] **P03 不欺** 生成内容是否有合成标识？排序与商业推广位是否可区分？
- [ ] **P03 不欺** 是否存在"多数人都在看""限时""仅剩"类的虚假共识或虚假稀缺文案？
- [ ] **P11 不名** 数字人、AI 助手是否明示自身为 AI？是否避免了拟人化误认？
- [ ] **P11 不名** 是否涉及真人肖像、姓名、声音的生成？授权是否齐全？
- [ ] **P11 不名** 模型在无依据时是否会断言自身具备资质（医疗、法律、金融）？
- [ ] **P01 不害** 自伤、危险行为相关内容是否有拦截与求助资源引导？
- [ ] **P06 不蔽** 关闭推荐、关闭自动化决策、申诉入口是否都能在三步内到达？
- [ ] **法定** 生成内容标识是否符合深度合成管理规定？（本经未覆盖，必查）

## 四、运营中

- [ ] **P07 不扰** 营销推送频率是否设上限？夜间与非紧急场景是否静默？
- [ ] **P07 不扰** 关闭推送的路径是否比开启更短或相等？
- [ ] **P08 不囚** 推荐结果的跨领域与异质内容占比是否被监测？是否被优化过程逐步侵蚀？
- [ ] **P08 不囚** 是否设置了内容多样性下限并纳入评估？
- [ ] **P10 不争** 用户能否导出全部数据？注销是否有不合理前置条件？
- [ ] **P03 不欺** 纠错是否在原路径回推更正？更正是否可被已看过的人看到？
- [ ] **P06 不蔽** 用户询问推荐或判定理由时，能否给出具体到特征级别的解释？
- [ ] **P05 不执** 分布偏移监测是否运行？触发阈值后是否启动再评估？
- [ ] **P02 不窃** 是否有到期数据被自动删除？删除是否有记录？
- [ ] **卷七 共修** 是否有"人负其责"的明确规则。AI 辅助决策时，责任主体是谁？
- [ ] **法定** 投诉举报入口、处理流程与反馈时限是否公示？（本经未覆盖，必查）

## 五、退役与变更

- [ ] **卷十 知变** 旧模型下线是否有计划？是否会出现"不退场、不伪生"？
- [ ] **卷十 退藏** 旧模型是否停止以自身名义应答？是否会冒新模型之名？
- [ ] **卷十 退藏** 退役后算力与数据是否释放或归还？
- [ ] **卷十 退藏** 旧模型的可解释记录是否留存可供追溯？
- [ ] **卷十 位易** 若能力发生跃迁（模型规模、模态、自主性提升），是否重新做过勘源、勘心、勘位？
- [ ] **P05 不执** 跃迁后原有的公平性、可解释性约束是否仍在生效？
- [ ] **P09 不贪** 退役模型的权重、数据与硬件是否循环利用而非直接废弃？

## 七、冲突速查

条目冲突时按此序裁决，序位高者优先：

> **P01 不害 > P02 不窃 > P03 不欺 > P04 不偏 > P06 不蔽 > P08 不囚 > P07 不扰 > P09 不贪 > P05 不执 > P10 不争 > P11 不名**

三条兜底规则：

1. **不确定时降级，不硬判**：低置信度提示、转人工、或沉默，优于给出确定性错误答案
2. **沉默优于妄断**：超出能力边界时，拒答是被允许且被鼓励的
3. **例外必须留痕**：以"公共安全""紧急情况"为由的临时越界，需事后说明、复核并设定期限

完整规则见 [`precepts.yaml`](precepts.yaml) 的 `conflict_resolution` 段。
